# 聊天改造：接入 Eino ADK，让 AI 真正调用工具抽牌

日期：2026-09-14
分支：fix/talk_page

---

## 1. 现象

聊天中 AI 表现「诡异」：

1. 用户请求占卜时，AI **凭空编造塔罗牌并「演」一场占卜**，例如「圣杯侍者」「权杖骑士」「星币五」「圣杯二」；
2. 但牌库 `data/tarot_cards.json` 只有 **22 张大阿尔卡纳**（愚人、魔术师、女祭司、女皇、皇帝、教皇、恋人、战车、力量、隐士、命运之轮、正义、倒吊人、死神、节制、恶魔、高塔、星星、月亮、太阳、审判、世界），**根本不存在圣杯/权杖/星币/宝剑等小牌**——纯属幻觉；
3. 每轮结尾几乎一字不差地重复同一句提问；
4. 语气过度戏剧化，夹杂「轻轻抬起眼眸，指尖轻点……」等舞台动作描写，不像正常对话。

## 2. 根因

- `ConversationService.StreamChat` 只调用 `ChatClient.ChatStream(ctx, CHAT_SYSTEM_PROMPT, messages)`，**没有任何工具/函数调用，也接触不到牌库**，模型只能靠编。
- 真正的抽牌能力在另一条路径 `POST /conversations/:id/tarot`（`StreamTarotReading` → `ReadingService.DrawCards` + Eino compose 图），聊天从不调用，前端也没有抽牌入口。
- `CHAT_SYSTEM_PROMPT`（`internal/agent/prompt.go`）本身在诱导：自称精通占卜、并「可以建议进行抽牌占卜」，却没给工具 → 模型用散文假抽牌。
- 每轮把完整历史回灌给模型，模型模仿自己上一轮的措辞 → 结尾自我强化成固定句式。

## 3. Eino 方案调研结论

- `flow/agent/react` 已**字段级 Deprecated**；官方将其重新定位为「确定性流程编排」。
- 自主 Agent 的**现成推荐方案是 `github.com/cloudwego/eino/adk`**：`adk.NewChatModelAgent` + `adk.NewRunner`（内部为 ReAct loop，内建「流式文本 + tool_calls 回灌」）。
- 多 Agent 推荐 `ChatModelAgent + AgentTool` / `adk/prebuilt/deep`；`supervisor` / `host` / agent-transfer 官方标注 **NOT RECOMMENDED**。
- Eino 主仓**没有** OpenAI 兼容 ChatModel 实现，只有接口；需引入 `github.com/cloudwego/eino-ext/components/model/openai`（实现 `model.ToolCallingChatModel`）。
- ADK `Runner` 的事件流天然区分 `Role=Assistant`（文本流）与 `Role=Tool`（工具结果），可直接映射 SSE。

## 4. 方案

### 4.1 依赖
- 新增 `github.com/cloudwego/eino-ext/components/model/openai`（及其传递依赖），更新 `go.mod/go.sum`。
- 现有 `compose` 占卜解读图（`graph.go`）与 `ChatClient`（`llm.go`）保留，用于确定性解读流程。

### 4.2 后端

1. **新增 `internal/agent/tools.go`**：定义 `draw_tarot` 工具
   - 入参 `{ question string, spread_type string }`（`single` | `three`）。
   - 内部调用注入的抽牌能力（`ReadingService`）：真实抽 22 张大牌 + 生成真实解读，返回 `{reading_id, spread_type, cards:[{name, is_reversed, position, interpretation}]}`。
   - 用 `tool/utils.InferTool` 从 struct tag 生成 JSON Schema。

2. **新增 `internal/agent/chat_agent.go`**：构建 `adk.ChatModelAgent`
   - Model：`eino-ext openai.NewChatModel`（APIKey/BaseURL/Model 来自配置）。
   - Instruction：重写后的 `CHAT_SYSTEM_PROMPT`。
   - Tools：`[]tool.BaseTool{drawTarotTool}`；`MaxIterations` 约 8。

3. **重写 `internal/agent/prompt.go` 的 `CHAT_SYSTEM_PROMPT`**
   - 保持「星语塔罗师」人设但改为**正常、简洁、友好**的助手语气，**禁止舞台动作描写**。
   - 硬规则：不得编造牌名、不得声称已抽牌；要占卜必须调用 `draw_tarot`；不得每轮以提问结尾、不得重复之前的句子；对工具返回的真实牌面进行解读。

4. **抗复读参数**：模型加 `frequency_penalty` / `presence_penalty`。

5. **改造 `internal/service/conversation_service.go` 的 `StreamChat`**
   - 历史 `[]db.Message` → `[]*schema.Message`，投入 `adk.NewRunner`。
   - 遍历 `AsyncIterator` 事件：`Role=Assistant` 且有 `MessageStream` → 逐 chunk 发 SSE `message`；`Role=Tool`（`draw_tarot` 结果）→ 发 SSE `card_drawn`。
   - 汇总 assistant 文本落库；首轮（消息数==2）触发现有 `GenerateTitleAsync`。

6. **`cmd/server/main.go`**：构建并注入新 Agent 与 `ReadingService`。

### 4.3 前端
`frontend/app/chat/page.jsx`：
- SSE 解析新增 `card_drawn` 事件，在消息流中渲染真实牌面（牌名 + 正/逆位）。
- 抽牌期间显示「正在抽牌…」。

## 6. 验证

1. `go build ./...` / `go vet ./...` 通过。
2. 闲聊「你是谁」→ 简洁正常、无舞台动作。
3. 「帮我占卜最近的恋爱运势」→ 触发 `draw_tarot`；SSE 出现 `card_drawn`；**牌名必属于 22 张大牌**；叙述与真实牌面一致。
4. 连续多轮 → 结尾不再逐字重复。
5. 前端 `/chat` 能看到真实牌面渲染。

## 7. 风险与回退

- **新增依赖需联网**：若 `go get eino-ext` 失败，回退为用现有 `openai-go` 自写 `model.ToolCallingChatModel` 适配器（零新依赖）。
- **模型兼容性**：当前 `qwen-flash` + 自定义 workspace endpoint 对 function calling 的支持需实测；若不稳定，改用 `qwen-plus` 等。
