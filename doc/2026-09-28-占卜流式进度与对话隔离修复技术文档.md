## 1. 问题清单与根因

### 问题 A：三张牌阵「不行」——抽牌后长时间无任何输出

> TODO 前端 2「三张牌的占卜还是不行」、4「3张牌逻辑不对」

**根因**（`backend-go/internal/service/conversation_service.go:249-338`，函数 `StreamTarotReading`）。

当前执行顺序是严格串行的三段：

| 阶段 | 代码位置 | 用户可见效果 |
|---|---|---|
| 1. 逐张推 `card_drawn` | 274-277 | 牌立刻出现（~0.6s） |
| 2. **同步阻塞** 调 LLM 生成每张牌的解读 | 284-288 → `CreateReadingWithCards` / `CreateReadingLangGraphWithCards` | 界面完全静止 |
| 3. 再调一次 LLM 流式生成「整体解读」 | 305-322 | 才开始逐字输出 |

阶段 2 的 LLM 调用次数：

- `single`：`CreateReadingWithCards` 内 1 次 `llm.Chat` → 阻塞 ~10s
- `three`：Eino 图内 `interpretCards` 3 次 `llm.Chat` + `synthesize` 1 次 `llm.Chat` = **4 次**，且 `graph.go:80` 是 `for` 顺序执行 → 阻塞 ~30s

阶段 3 又额外 1 次 `ChatStream`。所以 `three` 一次占卜共 **5 次 LLM 调用**，前 4 次全程无输出。

**判定**：这不是「牌阵逻辑算错」，而是**流式管道里插了一段同步批处理**。牌在 0.6s 出现后要空等 30s 才有第一个字。

### 问题 B：单张牌阵的解读重复出现两遍

> TODO 前端 7「单张解读出现了2遍，多张牌阵 似乎是有必要的」

**根因**：`single` 时同一张牌被解读了两次，两次内容都渲染到界面：

1. `CreateReadingWithCards`（`reading_service.go:151-166`）用 `BuildCardPrompt` 生成 → 写入 `reading_cards.interpretation`（prompt 要求 200-300 字）。前端 `TarotCard.jsx:195-198` 渲染它。
2. `StreamTarotReading:305-322` 用 `TAROT_READING_SYSTEM_PROMPT` 再生成一遍「整体解读」，且 `openaiMessages` 里已经塞进了第 1 步的解读（`contextMsgs`，300-303 行）→ 内容与第 1 步高度重合。前端 `page.jsx:413-424` 用「整体解读」面板渲染它。

`three` 时更严重：`reading_service.go:259-265` 把 Eino 图产出的 `state.Synthesis` 以 `"\n\n---\n**综合解读**: "` 为分隔符**拼进最后一张牌的 interpretation**，然后第 5 次调用又生成一遍综合解读。即出现「第 3 张牌卡片里嵌一段综合解读」+「整体解读面板又一段综合解读」。

**判定**：`single` 不需要「逐牌解读 + 综合解读」两层，多张牌阵需要。这与用户 TODO 原话一致。

### 问题 C1：对话界面的牌刷新后消失

> TODO 前端 8「对话界面的牌似乎没有了，很不对」

**根因**：聊天页用完牌后就丢了。

- `StreamChat`（`conversation_service.go:117-119`）在流式过程中推 `card_drawn`，前端 `chat/page.jsx:212-215` 攒进 `drawnCards`；
- `done` 时前端把它造成本地消息 `appendAssistant('', 'cards', drawnCards)`（`chat/page.jsx:224`）——**只存在于 React state，从不落库**；
- 保存 assistant 消息时（`conversation_service.go:124`）`type` 写死 `"text"`，**不写 `reading_id`**，DB 里没有任何线索能还原牌面。

所以：切换会话、刷新页面、重新进入聊天页，牌就没了。`draw_tarot` 明明已经建好了 `readings` / `reading_cards` 行，只是没有把消息和它关联起来。

### 问题 C2：占卜信息混进对话

> TODO 前端 9「占卜信息怎么混到对话里面去了，很不对的」

**根因**：占卜页和聊天页**共用同一套 conversations**，没有任何区分维度。

- 占卜页 `page.jsx:90-99` 的 `ensureConversation` 用 `GET /conversations` 取 `list[0]`，或 `POST /conversations` 新建；
- `StreamTarotReading:258` 往该会话写用户消息 `"🎴 塔罗占卜："+question`（`type="reading"`），`325` 写解读 assistant 消息；
- 聊天页 `chat/page.jsx:88-95` 拉的 `GET /conversations` 是**同一份列表**，于是点进去就是占卜记录；`loadConversations()`（`227` 行）还会把占卜会话顶到列表最前。

`conversations` 表有 `UserID`，但没有「这个会话属于哪个功能」的字段，`ListConversations`（`conversation_service.go:172`）也只有 `user_id` 一个过滤条件。

## 2. 设计决策

### 2.1 事件契约（`POST /api/v1/conversations/:id/tarot`）

新增一个事件类型 `card_interpreted`，并明确 `done` 的语义：

| event | data | 触发时机 | 变化 |
|---|---|---|---|
| `card_drawn` | `{name, is_reversed, position}` | 抽牌后逐张立即 | 不变 |
| `card_interpreted` | `{position, name, is_reversed, interpretation}` | **新增**：该张牌解读完成即推 | 新增 |
| `message` | `{delta}` | 主输出逐字 | 语义收窄，见下 |
| `done` | `{done, full_text, reading_id, msg_id}` | 结束 | 不变 |
| `error` | `{error}` | 失败 | 不变 |

`message` 事件的语义按牌阵分派（**这是消除重复解读的核心约定**）：

- `single`：`message` 流式输出 = **这张牌的解读本身**，落库到 `reading_cards.interpretation`。不再有独立的「综合解读」。
- `three`：`message` 流式输出 = **综合解读**。逐牌解读走 `card_interpreted`，不占用 `message`。

即：**一次占卜只有一条主输出流，界面上每段文字只出现一次。**

`done.full_text` 与上表一致（single = 牌解读，three = 综合解读）。

### 2.2 前端渲染规则

| 牌阵 | 逐牌解读 | 主输出 | 渲染位置 |
|---|---|---|---|
| `single` | 不单独产出（主输出就是它） | 牌解读 | `TarotCard` 卡片内的「AI深度解读」 |
| `three` | `card_interpreted` 逐张推 | 综合解读 | 各牌卡片内 + 独立的「综合解读」面板 |

因此 `single` **不再渲染**「整体解读」面板；`three` 保留。

### 2.3 会话按 channel 隔离

给 `conversations` 加 `channel` 列，取值 `chat` / `reading`：

- 聊天页：`GET /conversations?channel=chat`、`POST /conversations {channel:"chat"}`
- 占卜页 + 占卜历史：`?channel=reading` / `{channel:"reading"}`
- `GET /conversations` **默认返回 `chat`**（保持「不传参数 = 聊天」的直觉）；`channel=all` 表示不过滤。

历史数据用一次性 UPDATE 回填（判定规则：有 `type='reading'` 消息且**没有** `type='text'` 消息的会话 → `reading`）。

### 2.4 消息与牌面的持久关联

- `StreamChat` 从 `draw_tarot` 工具返回值里提取 `reading_id`，写到保存的 assistant 消息上；
- `GET /conversations/:id` 与 `GET /conversations/:id/messages` 返回的消息体上加 `cards` 数组（由 `reading_id` 反查 `reading_cards` + `tarot_cards`）；
- 聊天页对带 `cards` 的消息渲染 `CardStrip`，刷新后依然可见。

### 2.5 明确不做的部分

- 不动 `TAROT_READING_SYSTEM_PROMPT` / `CHAT_SYSTEM_PROMPT` 的文案（属于 prompt 调参，单独一轮）。
- 不加 `DELETE /readings/:id`。占卜历史的删除仍是「删除整个会话」，`ReadingHistory` 的确认文案保持不变。
- 不合并 `three` 的多张牌解读为「一次请求」（TODO agent 第 5 条）。原因：逐牌解读是多张牌阵的展示基础（用户已确认「多张牌阵似乎是有必要的」），合并成单次结构化输出需要引入 JSON 结构化解析，风险与收益不匹配。本轮改为**并发**执行逐牌解读来缩短耗时。
- 不动 `chat/page.jsx` 的会话切换/滚动逻辑。

// PreparedReading 是已落库、等待写入解读的占卜记录。
// 抽牌与解读拆开，是为了让流式占卜能在抽牌后立刻推送进度。
type PreparedReading struct {
	Reading  *db.Reading
	Cards    []db.ReadingCard       // 按 position 升序
	CardData map[uint]*db.TarotCard // card_id → 牌库数据
}

// PrepareReading 建 readings / reading_cards 行，不调用 LLM。
func (s *ReadingService) PrepareReading(question, spreadType, sessionID string, drawnCards []DrawnCard) (*PreparedReading, error) {
	sid := uuid.New().String()
	if sessionID != nil && *sessionID != "" {
		sid = *sessionID
	}

	reading := db.Reading{SessionID: sid, Question: question, SpreadType: spreadType}
	if err := s.DB.Create(&reading).Error; err != nil {
		return nil, err
	}

	for i, dc := range drawnCards {
		rc := db.ReadingCard{
			ReadingID:  reading.ID,
			CardID:     dc.ID,
			Position:   i,
			IsReversed: dc.IsReversed,
		}
		if err := s.DB.Create(&rc).Error; err != nil {
			return nil, err
		}
	}

	var rcs []db.ReadingCard
	s.DB.Where("reading_id = ?", reading.ID).Order("position ASC").Find(&rcs)

	cardIDs := make([]uint, 0, len(drawnCards))
	for _, dc := range drawnCards {
		cardIDs = append(cardIDs, dc.ID)
	}

	cardData := make(map[uint]*db.TarotCard, len(cardIDs))
	if len(cardIDs) > 0 {
		var cards []db.TarotCard
		s.DB.Where("id IN ?", cardIDs).Find(&cards)
		for i := range cards {
			cardData[cards[i].ID] = &cards[i]
		}
	}

	return &PreparedReading{Reading: &reading, Cards: rcs, CardData: cardData}, nil
}

// InterpretCard 非流式解读单张牌；LLM 不可用或失败时降级为牌义库文本。
func (s *ReadingService) InterpretCard(ctx context.Context, p *PreparedReading, rc *db.ReadingCard) string {
	card := p.CardData[rc.CardID]
	if s.LLM == nil || card == nil {
		return agent.GetBasicInterpretation(card, rc.IsReversed)
	}
	prompt := agent.BuildCardPrompt(card, rc.IsReversed, p.Reading.Question, rc.Position, p.Reading.SpreadType)
	text, err := s.LLM.Chat(ctx, agent.SYSTEM_PROMPT, prompt)
	if err != nil || strings.TrimSpace(text) == "" {
		return agent.GetBasicInterpretation(card, rc.IsReversed)
	}
	return strings.TrimSpace(text)
}

// StreamCardInterpretation 流式解读单张牌，onDelta 逐字回调，返回最终文本。
//
// 降级路径也会通过 onDelta 输出（一次性），保证界面上一定有内容。
// 返回的 error 只用于日志，调用方不需要中断流程。
func (s *ReadingService) StreamCardInterpretation(ctx context.Context, p *PreparedReading, rc *db.ReadingCard, onDelta func(string)) (string, error) {
	card := p.CardData[rc.CardID]
	if s.LLM == nil || card == nil {
		text := agent.GetBasicInterpretation(card, rc.IsReversed)
		onDelta(text)
		return text, nil
	}

	prompt := agent.BuildCardPrompt(card, rc.IsReversed, p.Reading.Question, rc.Position, p.Reading.SpreadType)
	stream, err := s.LLM.ChatStreamSimple(ctx, agent.SYSTEM_PROMPT, prompt)
	if err != nil {
		text := agent.GetBasicInterpretation(card, rc.IsReversed)
		onDelta(text)
		return text, err
	}
	defer stream.Close()

	var full strings.Builder
	var streamErr error
	for {
		delta, err := stream.Next()
		if errors.Is(err, io.EOF) {
			break
		}
		if err != nil {
			streamErr = err
			break
		}
		if delta == "" {
			continue
		}
		full.WriteString(delta)
		onDelta(delta)
	}

	text := strings.TrimSpace(full.String())
	if text == "" {
		text = agent.GetBasicInterpretation(card, rc.IsReversed)
		onDelta(text)
	}
	return text, streamErr
}

// StreamSynthesis 流式生成综合解读，onDelta 逐字回调，返回最终文本。降级行为同 StreamCardInterpretation。
func (s *ReadingService) StreamSynthesis(ctx context.Context, p *PreparedReading, interps []agent.CardInterpretation, onDelta func(string)) (string, error) {
	const fallback = "（综合解读暂时不可用，请先参考上方各张牌的解读）"

	if s.LLM == nil {
		onDelta(fallback)
		return fallback, nil
	}

	prompt := agent.BuildSynthesisPrompt(interps, p.Reading.Question)
	stream, err := s.LLM.ChatStreamSimple(ctx, agent.SYSTEM_PROMPT, prompt)
	if err != nil {
		onDelta(fallback)
		return fallback, err
	}
	defer stream.Close()

	var full strings.Builder
	var streamErr error
	for {
		delta, err := stream.Next()
		if errors.Is(err, io.EOF) {
			break
		}
		if err != nil {
			streamErr = err
			break
		}
		if delta == "" {
			continue
		}
		full.WriteString(delta)
		onDelta(delta)
	}

	text := strings.TrimSpace(full.String())
	if text == "" {
		text = fallback
		onDelta(text)
	}
	return text, streamErr
}

// SaveCardInterpretation 把解读写回 reading_cards。

func interpretCards(ctx context.Context, llm *ChatClient, state *ReadingState) (*ReadingState, error) {
	// 预分配 + 按下标写入，保证 Interpretations 与 CardsInfo 顺序一致
	interps := make([]CardInterpretation, len(state.CardsInfo))
	var wg sync.WaitGroup

	for i, ci := range state.CardsInfo {
		wg.Add(1)
		go func(i int, ci CardInfo) {
			defer wg.Done()

			build := func(text, status string) CardInterpretation {
				return CardInterpretation{
					CardID:         ci.ID,
					CardName:       ci.Name,
					IsReversed:     ci.IsReversed,
					Position:       ci.Position,
					Interpretation: text,
					Status:         status,
				}
			}

			prompt := BuildCardPrompt(ci.Card, ci.IsReversed, state.Question, ci.Position, state.SpreadType)
			text, err := llm.Chat(ctx, SYSTEM_PROMPT, prompt)
			if err != nil {
				log.Printf("LLM interpret failed for %s: %v", ci.Name, err)
				interps[i] = build(GetBasicInterpretation(ci.Card, ci.IsReversed), "fallback")
				return
			}
			interps[i] = build(strings.TrimSpace(text), "success")
		}(i, ci)
	}

	wg.Wait()
	state.Interpretations = interps
	return state, nil
}
```

func (s *ConversationService) DecorateMessages(msgs []db.Message) []MessageDetail {
	out := make([]MessageDetail, len(msgs))
	seen := make(map[uint]bool, len(msgs))
	readingIDs := make([]uint, 0, len(msgs))

	for i, m := range msgs {
		out[i] = MessageDetail{Message: m}
		if m.ReadingID != nil && !seen[*m.ReadingID] {
			seen[*m.ReadingID] = true
			readingIDs = append(readingIDs, *m.ReadingID)
		}
	}
	if len(readingIDs) == 0 {
		return out
	}

	var readings []db.Reading
	s.DB.Where("id IN ?", readingIDs).Find(&readings)
	spreadOf := make(map[uint]string, len(readings))
	for _, r := range readings {
		spreadOf[r.ID] = r.SpreadType
	}

	var rcs []db.ReadingCard
	s.DB.Where("reading_id IN ?", readingIDs).Order("position ASC").Find(&rcs)

	cardIDs := make([]uint, 0, len(rcs))
	for _, rc := range rcs {
		cardIDs = append(cardIDs, rc.CardID)
	}

	cardsByID := make(map[uint]db.TarotCard, len(cardIDs))
	if len(cardIDs) > 0 {
		var cards []db.TarotCard
		s.DB.Where("id IN ?", cardIDs).Find(&cards)
		for _, c := range cards {
			cardsByID[c.ID] = c
		}
	}

	byReading := make(map[uint][]CardBrief, len(readingIDs))
	for _, rc := range rcs {
		card := cardsByID[rc.CardID]
		brief := CardBrief{
			Name:         card.Name,
			IsReversed:   rc.IsReversed,
			Position:     rc.Position,
			PositionName: positionName(rc.Position, spreadOf[rc.ReadingID]),
		}
		if card.ImageURL != nil {
			brief.ImageURL = *card.ImageURL
		}
		byReading[rc.ReadingID] = append(byReading[rc.ReadingID], brief)
	}

	for i := range out {
		if out[i].ReadingID != nil {
			out[i].Cards = byReading[*out[i].ReadingID]
		}
	}
	return out
}

func (s *ConversationService) StreamTarotReading(ctx context.Context, conversationID uint, userID, question, spreadType string, writer func(event string, data string), readingSvc *ReadingService) error {
	if s.LLM == nil || readingSvc == nil {
		return errors.New("LLM or ReadingService not configured")
	}

	if spreadType == "" {
		spreadType = "single"
	}

	userMsg, err := s.AddMessage(conversationID, userID, "user", "🎴 塔罗占卜："+question, "reading")
	if err != nil {
		return err
	}
	_ = userMsg

	count := 1
	if spreadType == "three" {
		count = 3
	}

	drawnCards, err := readingSvc.DrawCards(count)
	if err != nil {
		return err
	}

	// 先推牌面：用户立刻看到抽到什么牌，不等解读
	for i, dc := range drawnCards {
		cardData := fmt.Sprintf(`{"name": %s, "is_reversed": %t, "position": %d}`, toRawJSON(dc.Name), dc.IsReversed, i)
		writer("card_drawn", cardData)
	}

	sessionID := fmt.Sprintf("conv_%d", conversationID)
	p, err := readingSvc.PrepareReading(question, spreadType, &sessionID, drawnCards)
	if err != nil {
		return err
	}

	// 主输出：single 是这张牌的解读，three 是三张牌的综合解读。
	// 两者互斥，界面上每段文字只出现一次。
	var mainText string

	if spreadType == "three" {
		interps := s.interpretAll(ctx, readingSvc, p, writer)
		mainText, _ = readingSvc.StreamSynthesis(ctx, p, interps, func(delta string) {
			writer("message", fmt.Sprintf(`{"delta": %s}`, toRawJSON(delta)))
		})
		readingSvc.SaveSynthesis(p, mainText)
	} else {
		mainText, _ = readingSvc.StreamCardInterpretation(ctx, p, &p.Cards[0], func(delta string) {
			writer("message", fmt.Sprintf(`{"delta": %s}`, toRawJSON(delta)))
		})
		readingSvc.SaveCardInterpretation(&p.Cards[0], mainText)
	}

	readingMsg, err := s.AddMessage(conversationID, userID, "assistant", mainText, "reading")
	if err != nil {
		return err
	}
	s.DB.Model(&db.Message{}).Where("id = ?", readingMsg.ID).Update("reading_id", p.Reading.ID)

	writer("done", fmt.Sprintf(`{"done": true, "full_text": %s, "reading_id": %d, "msg_id": %d}`, toRawJSON(mainText), p.Reading.ID, readingMsg.ID))

	if msgCount, err := s.GetMessageCount(conversationID); err == nil && int(msgCount) == 4 {
		go s.GenerateTitleAsync(conversationID)
	}

	return nil
}

// interpretAll 并发解读三张牌，每张牌完成即推 card_interpreted 事件。
// 返回按 position 升序排列的解读，可直接用于 BuildSynthesisPrompt。
func (s *ConversationService) interpretAll(ctx context.Context, readingSvc *ReadingService, p *PreparedReading, writer func(event string, data string)) []agent.CardInterpretation {
	interps := make([]agent.CardInterpretation, len(p.Cards))
	var wg sync.WaitGroup
	var mu sync.Mutex

	for i := range p.Cards {
		wg.Add(1)
		go func(i int) {
			defer wg.Done()

			rc := &p.Cards[i]
			text := readingSvc.InterpretCard(ctx, p, rc)
			readingSvc.SaveCardInterpretation(rc, text)

			interps[i] = agent.CardInterpretation{
				CardID:         rc.CardID,
				CardName:       p.CardData[rc.CardID].Name,
				IsReversed:     rc.IsReversed,
				Position:       rc.Position,
				Interpretation: text,
				Status:         "success",
			}

			mu.Lock()
			writer("card_interpreted", toRawJSON(map[string]any{
				"position":       rc.Position,
				"name":           p.CardData[rc.CardID].Name,
				"is_reversed":    rc.IsReversed,
				"interpretation": text,
			}))
			mu.Unlock()
		}(i)
	}

	wg.Wait()
	return interps
}
```

### 5.2 三张牌阵的进度可见性（问题 A 的核心断言）

启动后端（`GOCACHE` 同上）与 `next dev`，用 `curl -N`（不能加 `--compressed`，否则 gzip 会把事件攒到最后）观察时间戳：

```bash
curl -sN -X POST "http://127.0.0.1:8000/api/v1/conversations/$CID/tarot" \
  -H 'Content-Type: application/json' -H "Cookie: user_id=$UID" \
  -d '{"question":"我最近的工作运势如何","spread_type":"three"}' \
  -w '\n[%{time_total}]\n' | while IFS= read -r line; do printf '%s %s\n' "$(date +%s.%N)" "$line"; done
```

断言：

1. 3 条 `card_drawn` 出现在 T+2s 内；
2. 存在 ≥1 条 `card_interpreted`，且其时间戳 **早于**第一条 `message` 的 delta（证明进度在综合解读之前就推出来了）；
3. 3 条 `card_interpreted` 的 `position` 互不相同，覆盖 0/1/2；
4. 第一条 `message` 的时间戳 **明显早于** `done`（流式成立）。

### 5.3 单张牌不再重复

```bash
curl -sN ... -d '{"question":"...","spread_type":"single"}' | grep -c 'card_interpreted'
```

断言：

1. `card_interpreted` 条数 == **0**（single 不推逐牌事件）；
2. `GET /readings/:id` 返回的 `cards[0].interpretation` 与 `done.full_text` **字符串相等**；
3. 浏览器里单张占卜页的「综合解读／整体解读」面板**不存在**，解读只出现在牌面卡片内（Playwright 断言 `document.body.innerText` 中该段文本出现 1 次）。

### 5.4 三张牌的综合解读独立

断言：

1. `GET /readings/:id` 的 `synthesis` 非空；
2. 每张 `cards[i].interpretation` **不含** `---` + `**综合解读**` 字样；
3. `synthesis` 与任意 `cards[i].interpretation` 互不相等。

### 5.5 对话页牌面持久化（问题 C1）

1. 在 `/chat` 提问「帮我抽一张牌看看今天的运势」触发 `draw_tarot`；
2. `CardStrip` 在流式过程中出现；
3. **刷新页面**后，同一条 assistant 消息上方 `CardStrip` 仍在；
4. `GET /conversations/:id` 的该条消息 JSON 含 `reading_id` 非空、`cards` 长度 ≥1。

### 5.6 频道隔离（问题 C2）

1. `GET /conversations`（不带参数）→ 全部元素 `channel == "chat"`；
2. `GET /conversations?channel=reading` → 全部元素 `channel == "reading"`；
3. 在 `/` 完成一次占卜后，`/chat` 的侧边栏**不出现**该占卜会话；
4. 旧库升级：`BackfillConversationChannel` 执行后，`SELECT id, channel FROM conversations` 中「有 reading 消息、无 text 消息」的会话 `channel` 已为 `reading`；重复执行结果不变。

### 5.7 回归

- `GET /conversations/:id/messages` 返回体仍含 `id/role/content/type/reading_id/created_at`，`ReadingHistory` 能正常配对出记录；
- 聊天页普通闲聊（不触发 `draw_tarot`）行为不变：`done` 后回读，消息只有一条 assistant 回复；
- `draw_tarot` 的 `three` 牌阵（聊天页）耗时较改造前下降（`interpretCards` 并发）。

环境：Go 后端 `:8000`（MySQL `tarot` 库），`next start` `:3000`，模型 `qwen-flash`。

### 6.1 数据库迁移

### 6.2 SSE 事件时序（`curl`/python 逐字节读流）

**single**

```
  0.000s card_drawn        {"name": "...", "position": 0}
  0.150s message          第一个 delta
  2.072s done             全文 427 字，73 个 delta
```

| 断言 | 结果 |
|---|---|
| 首个 delta 时间 | **0.150s**（改造前需等 1 次同步 `llm.Chat`，约 10-15s） |
| `card_interpreted` 条数 == 0 | ✅ |
| 流式全文 == `cards[0].interpretation` | ✅（427 == 427，即**只存在一份解读**） |
| `synthesis` 为空 | ✅（前端因此不渲染第二个面板） |

**three**（4 次独立实测）

```
  0.000s card_drawn ×3        （位置 0/1/2 一次推齐）
  1.962s card_interpreted     position=1
  2.124s card_interpreted     position=2
  2.154s card_interpreted     position=0
  2.353s message              第一个 delta（综合解读开始流式）
  5.001s done                 综合解读 669 字，116 个 delta
```

| 断言 | 结果 |
|---|---|
| `card_drawn` 3 张、位置 0/1/2 | ✅ |
| `card_interpreted` 3 张、位置覆盖 0/1/2 | ✅（**推送顺序为完成顺序，如 [2,1,0]，前端按 position 归位**） |
| 逐牌解读早于主输出首个 delta | ✅（1.962s < 2.353s，进度确实先于综合解读） |
| 牌面出现到第一段解读正文 | **≈2.0s**（改造前牌面 0.6s 出现后空等 ≈30s） |
| 完整耗时 | **≈5.0s**（改造前 ≈30-40s） |
| `synthesis` 非空且 == `done.full_text` | ✅ |
| 各牌解读不含 `**综合解读**` 标记 | ✅（不再往最后一张牌里拼接） |
| `synthesis` 与各牌解读互不相同、各牌解读互不相同 | ✅ |

### 6.8 回归

- `GET /conversations/:id` 顶层字段 `channel` 新增，消息字段 `id/conversation_id/role/content/type/reading_id/created_at` **全部保留**（`cards` 仅在非空时出现）；
- `GET /conversations/:id/messages` 同样保留全部既有字段 → `ReadingHistory.collectReadings` 的配对逻辑不受影响（实测 `type=reading` 消息正常配对出 reading_id）；
- 无牌消息不出现 `cards` 字段，聊天页普通闲聊渲染路径不变；
- `npx next build` 通过；`gofmt -l` 无输出；`go vet ./...` 通过；浏览器 0 个 JS 错误。

复现脚本（本轮用完即删，此处保留方法）：SSE 时序用 `http.client` 逐块读流并打时间戳，**不要用 `curl --compressed`**（gzip 会把事件攒到流结束）；浏览器验收用 Playwright 精确选择器 `div.rounded-2xl.shadow-lg`（TarotCard 根节点）与 `div.bg-mystic-800`（牌条 chip），不要用宽松的 `.rounded-2xl`——它会同时命中外层容器，导致「3 张牌数成 4 张」的假失败。
