# 聊天页无法输入问题修复

日期：2026-09-14
分支：fix/talk_page
范围：仅前端 `frontend/app/chat/page.jsx`

---

## 1. 现象

用户进入 `/chat` 后**无法在输入框输入内容、无法向 AI 提问**，页面看起来「不可用」。

## 2. 证据

直接抓取服务端渲染的 `/chat` HTML：

```html
<textarea placeholder="输入你的问题... (Enter发送, Shift+Enter换行)" disabled="" ...>
```

输入框带有 `disabled` 属性。

## 3. 根因

`page.jsx` 中输入框与发送按钮的禁用条件为：

```jsx
disabled={isStreaming || !currentConversation}
```

而进入 `/chat` 时 `currentConversation` 初始为 `null`，且**页面从不自动创建或选中会话**（`initUser` 只负责加载会话列表）。因此：

- 首次进入（无历史会话）→ 必然无法输入；
- 只有手动点击「新对话」并成功创建后，输入框才恢复可用；
- 若创建/初始化失败，仅 `console.error`，界面无任何提示，表现为「完全用不了」。

即：**输入能力和「是否已有会话」被错误地耦合**，且缺少自动初始化与错误反馈。

## 4. 方案

仅修改 `frontend/app/chat/page.jsx`：

1. **新增 `error` 状态**，用于页面可见的错误提示，替代静默 `console.error`。
2. **自动初始化会话**：`ready` 后加载会话列表——
   - 列表非空 → 自动选中最近一条（后端已按 `updated_at DESC` 返回，取第一条）；
   - 列表为空 → 自动调用 `createConversation()` 新建并选中。
3. **输入框放行**：`textarea` 的 `disabled` 去掉 `!currentConversation`，只保留 `isStreaming`；发送按钮保留 `isStreaming || !input.trim()`。
4. **发送时懒创建兜底**：`sendMessage` 中若 `currentConversation` 为空，先 `await createConversation()` 取得会话再发送；创建失败则置 `error` 并复位。
5. **`createConversation` 返回新会话对象**（成功返回 `data`，失败返回 `null`），供自动创建与懒创建复用。
6. 各请求失败时 `setError(...)`，在消息区渲染错误提示。

后端 Go 代码、路由、cookie、SSE 均不改动（已单独验证正常）。

## 5. 涉及文件

- `frontend/app/chat/page.jsx`

## 6. 验证

- 硬刷新 `/chat`：输入框立即可用；无历史会话时自动出现并选中一个「新对话」。
- 输入问题回车 → 逐字流式回复 → 首轮对话后左侧标题自动更新。
- 停掉后端再刷新：页面显示错误提示，而非静默卡死。
- 已有历史会话时：自动选中最近一条并加载其消息。
