# 聊天（/chat）功能修复方案

日期：2026-09-14
分支：fix/talk_page
范围：让聊天页在浏览器中稳定可用（同源代理 + httpOnly cookie 会话 + SSE 健壮性 + 标题生成 + 导航入口）

---

## 1. 背景

前端已有 `frontend/app/chat/page.jsx`，后端 `conversations` 路由组与 `ConversationService`（SSE 流式）均已实现。用 curl 直连后端可完整跑通「建会话 → 发消息 → 流式返回」，但浏览器中聊天页基本不可用。

## 2. 根因分析（已实测验证）

### P0 — CORS 拦截 `X-User-Id`（浏览器端致命）
前端每个会话请求都带 `X-User-Id`（`page.jsx:82`），自定义头触发 CORS 预检。实测后端预检响应：

```
Access-Control-Allow-Headers: Origin,Content-Type,Accept,Authorization   # 不含 X-User-Id
Access-Control-Allow-Methods: GET,POST,PUT,DELETE,OPTIONS                # 不含 PATCH
```

浏览器因此拦截所有 `/conversations*` 请求，聊天页在浏览器里完全不可用。首页 `/readings/` 不带该头，所以正常。

### P1 — 身份方案混乱
- `POST /user/init` 未挂在 `UserID` 中间件组下（`main.go:50`），`c.GetString("user_id")` 恒为空 → 每次调用都发新 UUID。
- cookie 为 `httpOnly=true` 且跨域请求未带 `credentials`，cookie 永远存不下/发不出；`page.jsx:93` 又用 `document.cookie` 设一遍，重复且对 httpOnly 无意义。
- 结果：唯一身份来源就是被 CORS 挡住的 header。

### P1 — SSE 解析脆弱
前端只识别 `data:` 行，忽略 `event:` 与 `error` 事件（`page.jsx:205-229`）。后端出错发 `event: error` 时前端无法识别，流自然结束时也不复位 → 输入框永久卡在「流式中」。`abortControllerRef` 声明未使用。

### P1 — 聊天标题永不生成
`GenerateTitleAsync` 仅在 `StreamTarotReading` 中触发（`conversation_service.go:262`），`StreamChat` 未调用 → 纯聊天会话标题永远是「新对话」。

### P2 — 后端流错误处理与死代码
- `StreamChat` 把 `stream.Next()` 的任何 error 当 EOF（`conversation_service.go:71-78`），若首个 chunk 前出错会存下空 assistant 消息并继续发 `done`。
- `if writer != nil` 恒真；`ChatChunk`/`ChatDone`/`TarotStreamEvent`/`ChatStreamSimple`/`RequireUserID` 均为死代码。

### P2 — 入口与布局
- `layout.jsx` 导航无 `/chat` 入口，页面不可达。
- 聊天页 `h-screen` 嵌在带导航栏 + `py-8` 的 `<main>` 内，高度溢出。

---

## 3. 方案总览

1. **同源代理**：Next.js `rewrites` 把 `/api/*` 代理到 `http://localhost:8000/api/*`，前端改为同源相对路径 → 从根上消除 CORS 与跨域 cookie 问题。
2. **httpOnly cookie 会话**：身份只靠后端 cookie；前端不再存 localStorage、不再传 `X-User-Id`、不再手写 cookie。
3. **SSE 健壮性**：前端按 SSE 规范解析 `event:`/`data:` 块，识别 `done`/`error`，保证任何情况下复位 `isStreaming`；后端区分正常结束与错误，错误不落库。
4. **聊天标题生成**：`StreamChat` 正常完成后，首轮对话触发 `GenerateTitleAsync`。
5. **导航入口 + 布局**：导航栏加 `/chat` 链接；修正聊天页高度。

## 4. 详细改动

### 4.1 同源代理（前端）

文件：`frontend/next.config.js`

```js
const nextConfig = {
  reactStrictMode: true,
  swcMinify: true,
  async rewrites() {
    return [
      { source: '/api/:path*', destination: 'http://localhost:8000/api/:path*' },
    ]
  },
  images: { /* 保持原样 */ },
}
module.exports = nextConfig
```

文件：`frontend/app/chat/page.jsx`

```js
const API_BASE = process.env.NEXT_PUBLIC_API_URL || '/api/v1'
```

> `NEXT_PUBLIC_API_URL` 保持可选；未设置时走同源 `/api/v1`。注意：不要再设成 `http://localhost:8000/...`，否则又回到跨域。
> 其它页面（如首页 axios 调 `http://localhost:8000`）不在本次范围，暂不动。

### 4.2 httpOnly cookie 会话

#### 后端

文件：`backend-go/cmd/server/main.go`
把 `/user/init` 移入 `v1` 组（从而经过 `UserID` 中间件，能读到已有 cookie）：

```go
v1 := r.Group(cfg.APIV1Str)
v1.Use(middleware.UserID())
{
    v1.POST("/user/init", handler.InitUser())
    // ...其余保持不变
    // 删除原来的 user := r.Group(...) 块
}
```

文件：`backend-go/internal/handler/user.go`
逻辑已基本正确（有 cookie 则复用，否则生成并 `SetCookie`）。确认 cookie 属性：

```go
c.SetCookie("user_id", newUserID, 60*60*24*365, "/", "", false, true) // secure=false, httpOnly=true
```

同源代理下 `SameSite` 用默认（Lax）即可，无需额外设置。

文件：`backend-go/internal/middleware/user.go`
保留 `X-User-Id`/`X-User-ID` 作为 CLI/脚本兼容，cookie 作为浏览器主路径，无需改动。

文件：`backend-go/internal/middleware/cors.go`（防御性，直连时仍可用）
`AllowMethods` 加 `PATCH`；`AllowHeaders` 加 `X-User-Id`、`X-User-ID`。

#### 前端

文件：`frontend/app/chat/page.jsx`

- 删除 `localStorage.getItem/setItem('user_id')` 与 `document.cookie = ...`。
- `initUser` 无条件调用 `POST /api/v1/user/init`（带 cookie）：后端有 cookie 返回原 id，否则新建并下发 cookie。用一个 `ready` 状态替代 `userId`：

```js
const [ready, setReady] = useState(false)

const initUser = async () => {
  try {
    const res = await fetch(`${API_BASE}/user/init`, {
      method: 'POST',
      credentials: 'same-origin',
    })
    if (!res.ok) throw new Error('init user failed')
    setReady(true)
  } catch (err) {
    console.error('Failed to init user:', err)
  }
}

useEffect(() => { initUser() }, [])
useEffect(() => { if (ready) loadConversations() }, [ready])
```

- `getHeaders` 去掉 `X-User-Id`，所有 fetch 加 `credentials: 'same-origin'`（同源 fetch 默认即带 cookie，显式声明更清晰）：

```js
const getHeaders = () => ({ 'Content-Type': 'application/json' })
```

### 4.3 SSE 健壮性

#### 后端：区分 EOF 与错误

文件：`backend-go/internal/agent/llm.go`
`StreamHandler.Next()` 正常结束时返回 `io.EOF`，真实错误原样返回：

```go
import "io"

func (s *StreamHandler) Next() (string, error) {
    if s.done {
        return "", io.EOF
    }
    if !s.stream.Next() {
        s.done = true
        if err := s.stream.Err(); err != nil {
            return "", err
        }
        return "", io.EOF
    }
    evt := s.stream.Current()
    for _, choice := range evt.Choices {
        if choice.Delta.Content != "" {
            s.fullContent += choice.Delta.Content
            return choice.Delta.Content, nil
        }
    }
    return "", nil
}
```

文件：`backend-go/internal/service/conversation_service.go` → `StreamChat`
- 循环：`if errors.Is(err, io.EOF) { break }`；其它错误 `return err`（handler 会发 `event: error`）。
- 仅在正常结束时保存 assistant 消息并发 `done`；移除 `if writer != nil` 恒真判断。
- 保存后触发标题：首轮（消息数 == 2）时 `go s.GenerateTitleAsync(conversationID)`。

```go
var fullContent string
for {
    delta, err := stream.Next()
    if errors.Is(err, io.EOF) {
        break
    }
    if err != nil {
        return err
    }
    fullContent += delta
    writer("message", fmt.Sprintf(`{"delta": %s}`, toRawJSON(delta)))
}

assistantMsg, err := s.AddMessage(conversationID, userID, "assistant", fullContent, "text")
if err != nil {
    return err
}
writer("done", fmt.Sprintf(`{"done": true, "full_text": %s, "msg_id": %d}`, toRawJSON(fullContent), assistantMsg.ID))

if count, _ := s.GetMessageCount(conversationID); int(count) == 2 {
    s.GenerateTitleAsync(conversationID)
}
return nil
```

> `GenerateTitleAsync` 内部已自带「标题 == 新对话」与「消息 >= 2」校验，重复触发安全。
> `StreamTarotReading` 的同类循环建议一并改为 EOF 判断（可选，保持一致性）。

#### 前端：规范解析 SSE + 复位 + 错误提示

文件：`frontend/app/chat/page.jsx`

- 用 `AbortController`（存 `abortControllerRef`），`sendMessage` 前 abort 上一次、组件卸载时 abort。
- 按空行切分事件块，解析 `event:`/`data:`，按事件名分发：

```js
const reader = response.body.getReader()
const decoder = new TextDecoder()
let buffer = ''
let fullContent = ''
let finished = false

const handleEvent = (eventName, dataStr) => {
  let data
  try { data = JSON.parse(dataStr) } catch { return }
  if (eventName === 'error' || data.error) {
    throw new Error(data.error || 'stream error')
  }
  if (data.delta) {
    fullContent += data.delta
    setStreamContent(fullContent)
  }
  if (data.done) {
    finished = true
    setMessages((prev) => [...prev, {
      id: Date.now(), role: 'assistant',
      content: data.full_text || fullContent, type: 'text',
      created_at: new Date().toISOString(),
    }])
    loadConversations()
  }
}

while (true) {
  const { done, value } = await reader.read()
  if (done) break
  buffer += decoder.decode(value, { stream: true })
  const blocks = buffer.split('\n\n')
  buffer = blocks.pop() || ''
  for (const block of blocks) {
    let eventName = 'message'
    const dataLines = []
    for (const line of block.split('\n')) {
      if (line.startsWith('event:')) eventName = line.slice(6).trim()
      else if (line.startsWith('data:')) dataLines.push(line.slice(5).trimStart())
    }
    if (dataLines.length) handleEvent(eventName, dataLines.join('\n'))
  }
}
```

- `finally` 中统一：若未 `finished` 且无内容 → 显示错误气泡；无论如何 `setIsStreaming(false)`、`setStreamContent('')`。
- 非 2xx 响应：读取 `response.text()` 作为错误信息抛出，走到统一错误分支。

## 7. 风险与回退

- **Next rewrite 缓冲 SSE**：若 `next dev` 代理导致流式被缓冲，回退为「前端直连 `:8000` + 修正后端 CORS 头（补 `X-User-Id`/`PATCH`）」；或改用 App Router Route Handler 手工透传流。实施时以第 6 步实测为准。
- **cookie 丢失即新身份**：当前 `user_id` 不落库，清 cookie 会得到新身份、看不到旧会话。本次不处理（未来可加 users 表 + 会话绑定）。
- **`SameSite`**：同源代理下默认 Lax 即可；若未来改为跨站部署需显式设置。

## 8. 不在本次范围
- 对话内抽牌（`/conversations/:id/tarot`）前端接入。
- 历史记录页（`ReadingHistory.jsx` 仍为 mock）、`/readings/ws` WebSocket。
- 前端组件拆分（Sidebar/MessageList 等）与全局 API 客户端抽象。
- 首页 axios 直连 `:8000` 的统一改造。
